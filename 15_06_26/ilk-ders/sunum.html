Personel CRM Paneli Teknik Mimari ve Kod Analiz Sunumu

Bu doküman, React.js ve Vite mimarisi kullanılarak geliştirilen Single Page Application (SPA) tabanlı Personel Yönetim Paneli'nin iş mantığını, veri akışını ve kritik fonksiyonlarının derinlemesine satır analizi içermektedir [1, 2].

1. Dinamik Form Yönetimi ve Doğrulama Mekanizmaları

A. handleInputChange Fonksiyonu Analizi

Uygulamada her girdi alanı için ayrı fonksiyon yazmak yerine, tüm form akışını tek başına sırtlayan reaktif bir metot kullanılmıştır.

const handleInputChange = (e) => { const { name, value, type, checked } = e.target; const guncelDeger = type === "checkbox" ? checked : value; setForm(prev => ({ ...prev, [name]: guncelDeger })); };
  • Esnek Veri Yakalama: e.target üzerinden nesne parçalama (destructuring) yöntemiyle input bileşeninin tüm ayırt edici nitelikleri tek satırda ayrıştırılır.
  • Tipe Göre Değer Atama: Metinsel alanlar için value niteliği okunurken, aktiflik durumu ve stajyerlik gibi mantıksal alanlar için checked (true/false) durumu dinamik olarak seçilir.
  • Dinamik Anahtar Atama (Computed Property): [name] ifadesi sayesinde, HTML tarafındaki inputun ismi ne ise state nesnesi içindeki ilgili alan hedef alınır (Örn: name="eposta" ise doğrudan eposta güncellenir).
  • Durum Koruma (Spread Operator): ...prev ifadesi, React'in state'i tamamen ezme huyunu engeller; kullanıcının ad yazarken soyadı veya telefon bilgisini kaybetmemesini garanti altına alır.

B. formDogrula Fonksiyonu Analizi

Veritabanı güvenliği ve tutarlılığı için veriler üst bileşene gönderilmeden önce istemci tarafında sıkı bir denetime tabi tutulur.

const formDogrula = () => { const yeniHatalar = {}; if (form.ad.trim().length < 2) yeniHatalar.ad = "Ad en az 2 karakter olmalıdır."; if (form.soyad.trim().length < 2) yeniHatalar.soyad = "Soyad en az 2 karakter olmalıdır."; if (!form.eposta.includes("@")) yeniHatalar.eposta = "Geçerli bir e-posta giriniz."; setHatalar(yeniHatalar); return Object.keys(yeniHatalar).length === 0; };
  • Boşluk Manipülasyon Engeli: .trim() metodu metnin başındaki ve sonundaki boşlukları temizler. Kullanıcının sadece space tuşuna basarak zorunlu alanları geçmesi engellenir.
  • Hata Nesnesi Yönetimi: Hatalar anlık olarak yerel bir nesnede toplanır. Formun geçerlilik durumu tek bir mantıksal kontrole bağlanır: Nesne anahtar sayısı (Object.keys) sıfır ise form hatasızdır.

2. Durum (State) Yönetimi ve CRUD Algoritmaları

A. handleKaydet Fonksiyonu Analizi

Aynı arayüz bileşeninin hem yeni veri ekleme hem de var olan veriyi güncelleme yeteneğine sahip olmasını sağlayan polimorfik yapıdır.

const handleKaydet = () => { if (duzenlenenId) { // Güncelleme İşlemi setPersoneller(prev => prev.map(p => p.id === duzenlenenId ? { ...form, id: duzenlenenId } : p)); setDuzenlenenId(null); } else { // Yeni Kayıt İşlemi setPersoneller(prev => [...prev, { ...form, id: Date.now() }]); } setForm(bosForm); };
  • ID Kontrollü Dallanma: duzenlenenId durumunun doluluğuna göre algoritma yön değiştirir. State doluysa güncelleme, boşsa ekleme prosedürü işletilir.
  • Dizi Haritalama ile Güncelleme (.map): Liste taranır; sadece güncellenmek istenen ID ile eşleşen elemanın içi form verileriyle değiştirilir, diğer personeller (: p) listede orijinal haliyle bırakılır.
  • Zaman Damgalı Benzersiz Kimlik: Yeni kayıtlarda Date.now() kullanılarak milisaniye hassasiyetinde asla çakışmayacak yerel kimlik numaraları (ID) üretilir.

B. filtrelenmişPersoneller Algoritması Analizi

Uygulamanın performansını doğrudan etkileyen, ham veriyi bozmadan çalışan çalışma zamanı (runtime) süzgecidir.

const filtrelenmişPersoneller = personeller.filter(p => { const tamAd = `${p.ad} ${p.soyad}`.toLowerCase(); const metinEslesti = tamAd.includes(aramaMetni.toLowerCase()) || p.rol.toLowerCase().includes(aramaMetni.toLowerCase()); const departmanEslesti = seciliDepartman === "Tümü" || p.departman === seciliDepartman; const aktifEslesti = !sadeceAktif || p.aktif; return metinEslesti && departmanEslesti && aktifEslesti; });
  • Veri Mutasyonunun Önlenmesi (Immutability): Kullanıcı arama yaptıkça ana dizi temizlenmez. Sadece o render anına özel sanal bir liste süzülür. Arama temizlendiğinde veri kaybı olmadan eski liste ekrana döner.
  • Büyük/Küçük Harf Standardizasyonu: Kullanıcı girdileri ve personel isimleri .toLowerCase() ile eşitlenerek dil kaynaklı arama uyuşmazlıkları çözülür.
  • Seçmeli Checkbox Mantığı: !sadeceAktif || p.aktif yapısı kısa devre değerlendirmesi (short-circuit) kullanır. Filtre aktif değilse pas geçilir, aktifse personelin true olması zorunlu kılınır.

C. handleSil Fonksiyonu Analizi

Verilerin güvenli ve React felsefesine uygun olarak bellekten uzaklaştırılmasını sağlar.

const handleSil = (id) => { if (window.confirm("Bu personeli silmek istediğinize emin misiniz?")) { setPersoneller(prev => prev.filter(p => p.id !== id)); } };
  • Onay Mekanizması: window.confirm tarayıcı seviyesinde bir bariyer oluşturarak yanlışlıkla tıklamalarda veri kaybı yaşanmasını önler.
  • Filtreleme ile Ayıklama (.filter): Silme işlemi diziden eleman koparmak (splice) yerine, silinmek istenen ID haricindeki tüm elemanları yeni bir diziye kopyalayarak yapılır. Eşleşen ID süzgecin dışında kalır ve bellekten düşer.
